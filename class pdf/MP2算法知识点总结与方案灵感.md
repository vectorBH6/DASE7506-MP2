|---|---|---|
| 自回归语言模型与预训练 | 模型学到的是下一个 token 的统计规律；流畅或高概率不等于正确 | 不把嵌入中心性、答案格式、文本流畅度单独当成正确性证明 |

核心研究问题可以概括成一句话：**在训练集上学哪些候选证据和候选间关系，最能预测官方解析器认定的最终数值答案正确？**

## 1. Lecture 3：GPT 架构、预训练与现代模型组件

### 1.1 Transformer 组件和训练稳定性

Lecture 3 前半部分从 GPT-2 架构出发，解释深层 Transformer 如何组合表示：

- **LayerNorm** 在单个 token 的特征维度上做归一化：
  $y=\gamma\odot(x-\mu)/\sqrt{\sigma^2+\epsilon}+\beta$。它不跨样本或序列位置混合信息，$\gamma,\beta$ 允许模型重新学习尺度和偏移。
- **GELU 与位置逐点前馈网络**：前馈层把每个位置的表示扩展后再投影回原维度；同一组矩阵独立地作用于每个 token，不负责 token 间的信息交换。Attention 才负责跨位置混合。
- **残差连接** $x+F(x)$ 给梯度提供恒等路径；没有它，靠前层的梯度会随深度变小。讲义展示的例子里，残差连接显著改善早期层梯度。
- **Pre-Norm** 将归一化放在子层分支内，保留干净的残差通路，利于深层训练。它带来的另一面是残差流尺度仍可能随层数增长，所以现代架构也会使用 RMSNorm、QK-Norm 等做法。

**与 MP2 的关系：** 课程解释了隐藏表示为何适合做特征，但没有证明“语义中心的解答更正确”。MP2 提供的 candidate embedding 是固定的语义表示，几何邻近可以描述候选相似性或群体结构，却不是数值正确性的标签。要验证中心性是否有效，必须用训练标签做消融。

### 1.2 预训练目标、似然与置信度

自回归预训练以每个位置的下一个 token 为监督目标。交叉熵等于真实后续 token 的负平均对数概率：

$$
\mathcal{L}=-\frac{1}{N}\sum_t \log p_\theta(x_{t+1}\mid x_{\le t})
$$

这给每个 token 都提供训练信号；Perplexity 是 $\exp(\mathcal{L})$，可以粗略读成模型对下一个 token 的“有效选择数”。

推理时，模型将 logits 经 softmax 变为概率，再选择或抽样下一个 token。Temperature $T$ 通过 $z/T$ 调整分布尖锐度；top-k 或 top-p 截去尾部候选。两者控制随机性和多样性，**不会修复一个本来就排错的概率分布**。

**与 MP2 的关系：**

1. 如果以后尝试用 token 概率给候选排序，概率衡量的是模型觉得这段文本有多符合训练分布，不是文本是否符合题目或答案是否正确。
2. 候选长度会影响序列 log-probability；总 log-probability 会系统性惩罚更长文本，平均 log-probability 又可能偏爱重复、套话或易预测片段。分数应作为一个信号，不应视为 verifier。
3. 本作业提供的是固定嵌入，不提供可调用的生成模型或 logits；不能从 embedding 假装恢复候选的 token 置信度。

### 1.3 现代 LLM 组件：了解即可，别误当作作业方案

Lecture 3 后半介绍了现代架构演进：

- **RoPE** 在 attention 的 query/key 上以不同频率旋转向量，使注意力分数以相对位置差为核心；位置关系嵌入 attention，而不是简单加一个绝对位置表。
- **RMSNorm** 只按均方根缩放；**SwiGLU** 用乘法门控前馈特征。
- **Grouped-Query Attention、Multi-Head Latent Attention、稀疏/滑窗 Attention** 等减少 KV cache 或需要计算的上下文；稀疏 MoE 让总参数量与每 token 的活跃计算量分离。
- **MoE 路由**会出现专家负载坍塌，需要负载均衡机制；高容量的模型结构不代表小型候选选择器就需要 MoE。
- 讲义还介绍了 Muon、低精度训练、残差流扩展和模型蒸馏，主要用于大模型训练和服务效率。

**MP2 取舍：** 这些内容帮助理解 embedding 从何而来、神经模型怎样做表征和计算，但作业禁止额外预训练权重和外部数据，推理仅有 CPU 30 秒与 16 MiB 额外资源预算。对 4,755 个训练问题、每题四个候选来说，先试可解释的 NumPy 特征和小模型，通常更贴合任务与约束。

### 1.4 张量形状、权重共享与内存预算

来源：[Lecture 3，第 6–11、24–25 页](Lecture%203.pdf#page=6)。

输入 token ID 的形状是 `[B,T]`，隐藏状态是 `[B,T,d]`，词表 logits 是 `[B,T,V]`。各 Transformer block 保持隐藏状态形状，所以可以堆叠。训练可同时监督所有位置；逐 token 生成只取最后位置的 logits。

词嵌入矩阵和输出投影都含约 $Vd$ 个参数。GPT-2 示例中 $50257\times768=38,597,376$，共享这一矩阵会显著减少参数。共享需要引用同一个参数对象；给两个独立矩阵复制相同数值，不会自动减少存储或保证后续更新一致。

FP32 权重约为每参数 4 字节。全量 AdamW 训练还通常需要梯度及两份动量状态，合计约每参数 16 字节，尚未包含激活和其他缓冲。MP2 的 16 MiB 是**额外推理资产**预算；训练优化器状态无需随推理包发布，特征均值、方差、配置与降维矩阵则必须计入。

### 1.5 AdamW、数据切分与过拟合

来源：[Lecture 3，第 31、38–46 页](Lecture%203.pdf#page=31)。

- 自监督不等于没有标签：下一个 token 就是标签。滑窗会形成相关样本，不能先切出重叠窗口再随意分到训练和验证两边。
- AdamW 将 weight decay 与自适应梯度缩放分离。小样本拟合大模型时，训练损失下降、生成文本变流畅，都可能与验证损失上升同时发生。
- 训练循环包含清梯度、前向损失、反向传播、参数更新；训练/推理模式影响 dropout。恢复训练要恢复优化器状态，部署只保存前向推理所需参数。
- 对 MP2 的迁移是按**题目**划分交叉验证；同题候选、答案组和派生训练对必须留在同一 fold。标准化等统计量也只能在 fold 的训练部分拟合。

### 1.6 现代结构的数学要点

来源：[Lecture 3，第 51–61 页](Lecture%203.pdf#page=51)。

RoPE 对 query/key 的二维分量作旋转，核心关系是：

$$
\langle R_m q,R_n k\rangle=\langle q,R_{n-m}k\rangle
$$

该恒等式让旋转带来的位置依赖通过相对位置差表达；实际 $q,k$ 仍携带内容与上下文。它并不保证未经训练就能任意外推到更长序列。

RMSNorm 与 SwiGLU 可分别写为：

$$
\operatorname{RMSNorm}(x)=\gamma\odot
\frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2+\epsilon}}
$$

$$
\operatorname{SwiGLU}(x)=
\bigl(\operatorname{SiLU}(xW_1)\odot xW_2\bigr)W_3
$$

GQA 让多个 query head 共享 key/value head；MLA 用低维潜变量压缩 KV；稀疏注意力只读取部分位置；序列压缩再降低参与 attention 的位置数。它们减少不同的成本，不能统一理解为“attention 都变成线性复杂度”。

讲义的 mHC 案例用多个残差流及受约束的混合矩阵，并通过 Sinkhorn–Knopp 迭代近似实现双随机约束，以控制混合通路的放大。Muon 则将二维权重矩阵的动量作近似正交化：

$$
M_t=\mu M_{t-1}+G_t,\qquad
O_t\approx UV^\top,\qquad
W_{t+1}=W_t-\eta O_t
$$

其中 $M_t=U\Sigma V^\top$；实际用迭代近似替代每步精确 SVD。讲义中的 embedding、输出头和偏置仍采用 AdamW。FP4 训练关注低精度数值与训练适配，也不等于把任意模型直接转为 4 bit 就能保持效果。

### 1.7 蒸馏与多 token 预测

来源：[Lecture 3，第 57、62 页](Lecture%203.pdf#page=62)，[Lecture 5，第 13–15 页](Lecture%205.pdf#page=13)。

传统蒸馏常学习教师的软分布；LLM 数据蒸馏也可以只使用教师生成的回答进行 SFT。On-policy 蒸馏则让学生采样，教师对学生实际访问到的输出给信号。反向 KL 对“学生在教师低概率区域放置质量”惩罚较强，可能产生 mode-seeking 行为；这不是多样性或正确性必然改善的保证。

多 token 预测通过辅助目标训练预测后续多个 token；讲义将其列为前沿训练结构之一，未给 MP2 可直接复用的训练代码。现有材料对 GRPO 和蒸馏主要是引介/后续课程预告，不能把本套 PDF 当成完整的 GRPO 实现教程。

## 2. Lecture 4：监督微调、指令微调、LoRA 与 MoE

### 2.1 分类微调：把预训练表示用于标签决策

分类微调将语言模型词表输出头换成固定类别输出头，例如二分类的 Linear(隐层维度, 2)。常见做法是冻结大部分预训练参数，只更新新输出头或末端若干层；分类损失使用交叉熵，预测从 logits 的 argmax 得到。因果语言模型只让最后位置看到完整输入，所以课程分类示例使用最后 token 的 logits 作样本级分类。

课程示例中，只训练输出头不够；解冻最后一层 block、归一化层和分类头效果明显更好，全量微调再有小幅提升。微调学习率需要明显小于预训练学习率，因为预训练模型已经处于有用解附近，大步更新容易破坏现有表示。

**与 MP2 的关系：** 四选一可视为候选排序/分类，但训练对象不一定要是大模型。可以从每个候选提取特征，训练一个小型候选正确性估计器，或直接训练同题答案组之间的排序器。该方法正好利用项目允许的训练参考答案，不需要改变固定候选或部署额外的大模型。

### 2.2 指令微调：数据格式和损失掩码就是方法的一部分

指令微调通常不改模型架构和 next-token 目标，而是把指令、可选输入、期望回答按稳定模板拼起来。讲义强调：

- 训练时与推理时的模板标记必须一致；训练数据格式不一致会让模型学会错误续写模式。
- 按 batch 的最长样本动态 padding 比把全数据 pad 到统一最大长度省计算；长度分桶还能减少无效 padding。
- targets 比 inputs 错开一个 token：输入位置 $t$ 的监督目标是 token $t+1$。
- PyTorch 的 ignore_index=-100 可屏蔽 padding 或不想计算损失的位置；对 EOS 的处理要保留停止信号，否则模型可能学不会何时结束。
- 是否把 prompt token 也纳入损失，是一个需要实验验证的选择。只训练 response 可以集中梯度；连 prompt 一起训练则能得到更多监督位置。

**与 MP2 的关系：** 项目选择方法的协议也类似一种接口契约：返回值必须是 0–3 的 Python 整数、顺序必须与 bank 一致、只允许用传入文本和 embeddings。方法即使统计上不错，只要依赖 ID、误读候选顺序或返回协议错误，也不能通过评测。

### 2.3 LoRA：低秩地学习模型更新

全量微调需要保存权重、梯度和优化器状态。LoRA 保持原权重 $W$ 冻结，只学习低秩更新：

$$
W'=W+\frac{\alpha}{r}AB,\qquad A\in\mathbb{R}^{d_{\mathrm{in}}\times r},\quad B\in\mathbb{R}^{r\times d_{\mathrm{out}}}
$$

秩 $r$ 控制更新容量，$\alpha/r$ 缩放更新。常见初始化让 $A$ 随机、$B=0$，于是训练开始时模型行为和基座完全相同；若 $A,B$ 都为零，梯度会无法启动。LoRA 可合并回原权重以免推理额外开销，也可以保持分离以共享一个基座。

讲义同时提醒 LoRA 不是万能压缩：低秩更新容量不足时会掉点；小模型上 LoRA 可能因为额外矩阵运算反而更慢；部署收益主要是训练状态和 checkpoint 更小。**MP2 不需要在 Qwen 上跑 LoRA**：作业已给固定候选和表示，且不分发基座权重。LoRA 原理可借鉴的是“限制参数、控制容量”的思路，实做可以是轻量线性/小型非线性排序器。

### 2.4 MoE：模型容量与单 token 计算的分离

MoE 以 router 为 token 选择少量专家。总参数随专家数增加，每 token 计算量主要由激活专家数决定；但所有专家权重仍需驻留，路由还会带来通信和负载不均衡问题。它适用于大型模型在容量和推理成本间的折中，不是小型选择任务的默认答案。

### 2.5 PEFT 变体与 LoRA 的适用条件

来源：[Lecture 4，第 46–62 页](Lecture%204.pdf#page=46)。

| 方法 | 主要变化 | 应记住的代价或边界 |
|---|---|---|
| LoRA | 冻结基座，学习低秩更新 | 节省训练状态和任务增量参数，基座仍要参与计算 |
| QLoRA | 量化冻结的基座，训练 adapter | 包含量化/反量化处理，不能只统计 adapter 就忽略基座 |
| rsLoRA | 将常见的缩放改为 $\alpha/\sqrt{r}$ | 调整 rank 增大时的更新尺度 |
| DoRA | 分开学习权重的幅度与方向 | 方向采用低秩更新，训练有额外归一化 |
| LoRA+ | 两个低秩因子使用不同学习率 | 多一个学习率比例需要选择 |
| 多 adapter 服务 | 共享基座，为请求选择不同 adapter | 合并后推理简单；不合并有额外矩阵运算和调度 |

讲义讨论了 adapter 容量不足、batch 大小、放置层位置等条件。MLP 含较多参数，只给 attention 加 adapter 未必是最佳参数分配。讲义的“约 10 倍学习率”和每参数信息容量是特定研究设置下的经验观察，应与实验条件一起理解，不能直接变成 MP2 小网络的通用超参数定律。

### 2.6 MoE 路由与负载均衡

来源：[Lecture 4，第 63–70 页](Lecture%204.pdf#page=63)。

先计算专家 affinity，取 top-k，再对所选专家权重归一化并加权求和。若早期较强的专家获得更多 token、梯度和进一步提升，会出现正反馈与路由坍塌。

传统做法在语言模型目标上加入负载均衡辅助项；讲义还介绍只对**选择分数**加专家偏置，并按实际负载调整偏置，混合输出时仍用原始 affinity。细粒度专家增加组合空间，共享专家承载常见知识。不同实现对 top-k 负载统计的归一化不同，辅助损失的数值尺度也会不同。

MP2 可借鉴“让不同证据各司其职”的建模思想，但不必实现专家网络。若不同答案票型确实需要不同策略，可以先使用票型交互特征，而不是给每种票型训练一个数据更少的独立模型。

### 2.7 标签不平衡与评估口径

来源：[Lecture 4，第 7–8、14、39–42 页](Lecture%204.pdf#page=7)。

多数类别占比高时，单纯候选级 accuracy 可能很漂亮，却没有选择价值。课堂垃圾短信例子使用下采样展示这个问题；实际可以考虑加权损失，但选择取决于目标分布。

MP2 应以“每题选中正确答案”为主指标。候选二分类准确率、训练 loss、格式质量均只能作为辅助。训练集中的同题候选也不是独立样本，不能把 $4755\times4$ 当成同等数量的独立题目。

## 3. Lecture 5：推理、数学验证、CoT、自一致性与 ReAct

### 3.1 推理痕迹可以有帮助，也可以“说得像对的”

讲义将 LLM reasoning 作工程定义：先生成中间步骤，再给最终答案。它是自回归概率生成，不是保证每一步遵守规则的符号引擎；解释流畅、步骤多、语气自信，都不保证结论正确。CoT 的潜在好处是把复杂任务分解为序列步骤，并让模型有机会在后续 token 中修正；代价是更多推理 token、延迟和过度思考风险。

这对 MP2 很关键：官方指标只评最终数值答案，不检查证明过程。因此，候选“推理是否严格正确”与“官方是否给分”不是同一目标。若模型在中间推导有错但数值答案碰巧正确，官方仍会接受；若过程写得漂亮却答案错，仍然不得分。

### 3.2 Verifier 与 scorer 的差别

- **Verifier（验证器）** 有已知参考答案，可抽取最终答案、规范化，再判断数值等价。适合数学、代码等易验证领域。
- **Scorer（打分器）** 在测试时没有 gold，必须比较候选自身特征。可以是格式/长度规则、语言模型评审、模型 token 置信度等，但它只能排序，不能确认真伪。
- **LLM judge** 灵活却贵，且带有评审模型自己的偏差；启发式便宜透明却容易被格式利用；模型置信度便宜却可能偏爱自信错误。

Lecture 5 的数学验证流水线是：生成答案 → 抽取最后一个 boxed 结果 → 规范化表达式 → 用等价性而非字符串相同检查 → 处理多部分答案 → 汇总指标。课程也展示了 parser 的漏洞：单位、变量赋值、括号区间等可能解析错；一旦 parser 变成奖励，模型可能学会利用漏洞。

**MP2 的关键对应：** 项目的官方规则更窄：用 `code/common.py` 中的 `parse_answer` 解析候选和 gold，比较规范化后的 `Fraction` 字符串。解析器优先取最后一个 `####` 后的内容；没有 `####` 时取最后一个 `\boxed{}` 内容；随后抓取其中第一个整数、小数或分数。它不验证中间算术、不读懂单位，也不做完整数学等价推理。训练标签应按这个真实评分逻辑构造，不要凭人工语义另造目标。

### 3.3 CoT 与自一致性：多条路径，最终答案投票

Few-shot CoT 用带推理过程的例子示范解题格式；Zero-shot CoT 用 “Let’s think step by step” 之类的提示触发解释。讲义强调提示词本身能显著改变结果，且早期 CoT 增益有模型规模门槛；较小模型也可能因为专门训练过推理数据而受益。

Self-Consistency 的核心是采样多条推理链 $r$，抽取各自最终答案 $a$，然后投票：

$$
\hat{a}=\operatorname*{arg\,max}_a \sum_i \mathbf{1}[a_i=a]
$$

直觉是正确推导更可能汇聚到同一个答案，而错误推导更分散。它收敛到答案分布的众数，不要求正确答案概率大于 1/2。若错误集中为一个系统性错误，众数投票会稳定地选错；更多样本不一定改善这种偏差。讲义中 Self-Consistency 对 PaLM-540B 的 GSM8K 报告从 56.5% 提升到 74.4%，但要多次生成，成本随路径数量增加；这只是不同模型/数据上的文献结果。

**MP2 的迁移限制：** 作业不是现场对同一个模型抽样，而是四个已生成候选。答案票数可作强基线，但四条候选可能共享模型偏差，不能假设错误彼此独立。项目测试集专门要求每组至少出现两个不同的有效解析答案，训练和验证较容易；因此测试时单纯多数投票可能明显失灵，且不应靠 test 标签调节投票阈值。

### 3.4 ReAct：通过环境观察减少纯语言推断的盲点

ReAct 交替产生 Thought、Action、Observation。Thought 更新语言上下文，Action 调用搜索/lookup/finish 等工具，Observation 将外部结果写回上下文。它比纯 CoT 多了对外部环境的接地能力，但会增加调用成本、上下文长度、无效搜索和推理循环风险。数学任务若能调用计算器或 SymPy，工具可以检查算术；但本 MP2 的推理接口只应在四个固定候选中选择，不能测试时调用外部 API、生成新解答或引用外部模型。

### 3.5 Tokenizer、KV cache 与测时

来源：[Lecture 5，第 21–39 页](Lecture%205.pdf#page=21)。

BPE 将文本映射为子词 token；词表大通常意味着词表矩阵更大，同时部分文本需要更少 token。字符数、空格分词数和模型 token 数不能互换。本项目不附带完整 tokenizer，因此轻量特征应明确叫“字符数”或“正则词数”，不能把它们标成 Qwen token 数。

KV cache 缓存已处理前缀的 key/value，使后续步骤无需重复计算前缀投影和前馈层。课程图中的 $O(n^2)\to O(n)$ 描述重复处理的 token 位置数量；普通全注意力下，新 query 仍须读取历史 KV，不能据此宣称全部解码计算变成线性。

课程对 `torch.compile` 的性能演示区分编译预热和稳定运行。MP2 的计时规则包含新进程启动、import、载入与预处理，所以不能把首次编译/载入耗时从最终测量里删掉。小网络部署为 NumPy 前向能够避免为几次矩阵乘法引入大型推理运行时。

### 3.6 图片页补查：答案抽取与数学等价

来源：[Lecture 5，第 45、47–52、56 页](Lecture%205.pdf#page=45)。

第 45 页代码截图的 boxed 抽取器会扫描嵌套花括号，并在找不到 boxed 时按配置回退到最后一个数字或整段文本；第 49 页截图使用 SymPy 解析及隐式乘法；第 52 页再按元组/列表逐项检查。上述实现比 MP2 的官方正则 parser 更宽泛。

因此不能直接把课堂抽取器替换进作业。特别是 `\boxed{\frac{1}{2}}`、科学计数法、百分号和带单位答案，课堂与作业的行为可能不同。合法的改进是利用额外解析得到特征；最终答案分组、训练标签和官方评分仍使用原 `parse_answer`，并将 None 与合法值严格区分。

### 3.7 CoT 消融对报告设计的启发

来源：[Lecture 5，第 64–68、79–81 页](Lecture%205.pdf#page=64)。

课程比较“只写方程”“用无意义 token 增加计算”“先给答案再写推理”等设置。这些实验说明，在所研究的模型和任务上，单纯增加长度不能解释全部 CoT 收益。早期论文中约 100B 的规模观察也不是今天所有训练配方下的硬门槛。

对 MP2，可以分别测试答案票数、长度/格式、embedding、题目与文本关系、算术一致性。**删除显式推理文本特征后，固定 embedding 仍可能包含整条推理的信息**，所以这种消融不能命名为“完全不用推理”。真正的“题目 + 最终答案”基线必须同时去掉全文 embedding 和推理文本特征。

ReAct 的搜索失败率、CoT 的幻觉比例都是讲义所引用任务设置的统计，不应外推为 GSM8K 的错误比例。其可迁移部分是把可验证的局部算术证据纳入评分，并将“算术计算没错”与“题意理解正确”分开。

## 4. Lecture 6：推理时扩展、自我修订、RLHF 与 RLVR

### 4.1 Inference-time scaling：不改参数，多花推理预算

训练时计算改变权重，推理时扩展保持权重不变但每题花更多 token 或调用。课程比较三种模式：

1. **CoT：** 一条更长的串行推理。
2. **Self-Consistency：** 并行生成多个答案再投票。
3. **Self-Refinement：** 先答、再批评、再修订，多轮串行调用。

Temperature $T$ 对 logits 除以温度后做 softmax。$T<1$ 分布更尖锐，$T>1$ 更平；top-p 保留累计概率达到阈值的最小 token 集合并重新归一化。两者主要控制样本多样性，不保证准确度。采样使答案变得不一样，是获得互补候选的途径，不是“答案变正确”的充分条件。

讲义在 MATH-500/Qwen3 0.6B 上示范了计算-准确率折中：greedy base 15.2%，CoT 40.6%；CoT 加自一致性、样本数 10 到 52.0%，但时间约为基线的 85 倍。单独调 temperature/top-p 没带来相当的准确率提升。**这些是课程示例，不可直接外推到 MP2。**MP2 已冻结四个候选，最多把投票结构迁移过来；不能在评测时增加生成调用。

### 4.2 Best-of-N 与候选评分

Best-of-N 先得到多个答案，再用 scorer 选一个；瓶颈经常是评分，而不是生成。课程例子包括：

- 规则分数：能否抽出 boxed 答案，加上长度奖励。廉价、可解释，但容易偏好短而规整的错解。
- 模型 log-probability：将实际候选 token 在上下文中的条件概率相乘，通常在 log 空间求和避免下溢。平均答案 token log-probability可减轻长度差异：
  $s(y\mid x)=\frac{1}{|y|}\sum_t\log p(y_t\mid x,y_{<t})$。
- LLM judge：能评多维质量，但更贵，可能继承偏差。

**置信度不等于正确性。**模型会给符合熟悉语言模式但事实错误的答案高概率；求和会偏短，求均值又会偏向重复或模板化片段。因此 log-probability、长度、格式等应作为候选特征，而非单独判据。项目没有提供生成时 logits，不能直接复刻课程的语言模型置信度实验。

### 4.3 Self-Refinement：反思并不保证纠错

Self-Refinement 先生成初答，让模型批评，再按批评修订，可迭代并用 scorer 决定接受还是拒绝。它适用于可生成新解答的流程；但课程结果显示收益有限、迭代可能退化、评分器可能把“更像模型偏好的答案”误判成更正确。尤其是 log-probability 评分可能接受自信错误。多轮调用的计算代价也高。

对 MP2 而言，候选集固定，输出只能是候选索引，所以不能靠改写候选来修订；可借鉴的是“对每个候选分别评分，再用证据融合”的思想。

### 4.4 RLHF、DPO 和 RLVR：奖励定义决定优化方向

RLHF 通常从偏好比较拟合奖励模型，再用 PPO 在 KL 约束下优化策略。Bradley–Terry 偏好模型常写为：
$P(y^+\succ y^-\mid x)=\sigma(r(x,y^+)-r(x,y^-))$。
KL 项让新策略不要为追逐代理 reward 而偏离参考模型。DPO 将奖励写成 policy/reference 的 log-ratio，直接对偏好对做分类式优化，省去在线 RL 循环。

Lecture 6 列出的 reward hacking 包括冗长偏差、谄媚、过度拒答、多样性下降和校准变差：模型会优化奖励代理而非目标本身。RLVR 则把奖励换成数学/代码 verifier 的确定性结果，标签更客观、易复现，但 verifier 的误判会成为漏洞。

**与 MP2 的关系：** 有训练参考答案时，直接按官方解析器产生监督标签比构造人工偏好奖励更直接。若训练候选评分模型，它学到的也是对 benchmark 的小型代理规则，因此需要留出验证集做校准、消融与错误分析，并在测试前冻结。

### 4.5 自一致性、覆盖率与预算分配

来源：[Lecture 6，第 16–23、40–41 页](Lecture%206.pdf#page=16)。

Self-Consistency 可理解为对推理路径作边缘化：

$$
p(a\mid x)=\sum_r p(r,a\mid x)
$$

频率投票用有限采样近似答案分布。只有在采样满足相应稳定性条件、且正确答案是唯一众数时，增大样本数才有一致性保证。同一生成模型的系统性错误、少量候选与样本相关性都会影响收益。

必须区分 coverage（候选中是否至少有一个正确答案）与 selection accuracy（是否选中了正确答案）。MP2 题库保证 coverage 为 100%，改进重点因此是选择能力。没有必要把课程中的继续生成、搜索或修订预算原样移入本项目。

DeepConf 类方法把 token 置信度用于筛选推理链再投票。项目没有这些 token 概率，可保留“先评证据再聚合”的思想，并训练小评分器；将这个派生方案描述为学习排序，不能称为复现 DeepConf。

补充实现细节：top-p 要保留使累计概率首次跨过阈值的 token；只用累计概率小于阈值的条件，可能保留不足的质量。这个细节是课程采样实现的一部分，本次固定候选任务无需重新实现采样器。

### 4.6 自我修订何时会退化：课堂思考题的推导

来源：[Lecture 6，第 38、42 页](Lecture%206.pdf#page=42)；以下递推为对讲义问题的数学推导。

设一次修订将错答改对的概率为 $a$，将对答改错的概率为 $b$，当前准确率为 $p_t$，则：

$$
p_{t+1}=a(1-p_t)+(1-b)p_t
=a+(1-a-b)p_t
$$

当 $0<a+b<2$ 时，其稳定点为 $p_\infty=a/(a+b)$。一轮有益的条件是 $a(1-p_t)>bp_t$。这解释了为什么“多反思一次”没有普遍的单调提升保证。MP2 的类比是：允许覆盖多数票可以修复多数错误，也可能把本来正确的多数票推翻；要同时统计这两种变化。

### 4.7 Bradley–Terry、PPO、DPO 的目标函数

来源：[Lecture 6，第 50–60 页](Lecture%206.pdf#page=50)。

奖励模型通过成对比较学习：

$$
L_{\mathrm{BT}}=-\mathbb E\log\sigma(r(x,y^+)-r(x,y^-))
$$

同一问题的所有 reward 同加一个常数，不影响成对概率。这也说明纯粹给同题所有候选加同一项，无法改变排序。

RLHF 常优化：

$$
J(\pi)=\mathbb E_{y\sim\pi}[r(x,y)]
-\beta D_{\mathrm{KL}}(\pi(\cdot\mid x)\Vert\pi_{\mathrm{ref}}(\cdot\mid x))
$$

文本中的状态是问题与已生成前缀，动作是下一个 token，整个回答是一个 episode。Policy gradient 用 advantage 加权 log-probability 梯度。PPO 引入相对旧策略的概率比值，并对代理目标裁剪：

$$
\rho_t=\frac{\pi_\theta(y_t\mid s_t)}{\pi_{\mathrm{old}}(y_t\mid s_t)},\qquad
L_{\mathrm{clip}}=\mathbb E\min\bigl(\rho_t\hat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t\bigr)
$$

这是优化的代理目标，裁剪本身并不构成总体策略 KL 的硬约束。传统 PPO-RLHF 还要策略、参考、reward、value 等模型；GRPO/RLOO 的一项简化是用同题其他采样输出形成 baseline，避免单独的 value model。

令 $h_\pi$ 表示好坏回答的 policy/reference log-ratio 之差，DPO 目标为：

$$
h_\pi=\log\frac{\pi(y^+\mid x)}{\pi_{\mathrm{ref}}(y^+\mid x)}
-\log\frac{\pi(y^-\mid x)}{\pi_{\mathrm{ref}}(y^-\mid x)},\qquad
L_{\mathrm{DPO}}=-\mathbb E\log\sigma(\beta h_\pi)
$$

对 MP2，最直接的迁移是用训练 gold 形成“正确答案组优于错误答案组”的对，学习 BT 型小排序器。它不需要语言生成 policy 或 reference model，属于**监督成对排序**，不能仅因损失像 logistic 就称为 DPO 或 RLHF。

### 4.8 其他偏好优化方法与项目取舍

来源：[Lecture 6，第 61–67 页](Lecture%206.pdf#page=61)。

| 方法 | 主要训练信号 | 目标或关键变化 | MP2 中的用途 |
|---|---|---|---|
| IPO | 偏好对 + 参考模型 | 将 log-ratio margin 回归到有限目标 | 理解无穷放大 margin 的过拟合风险 |
| KTO | 单条好/坏标签 + 参考模型 | 相对于参考点构造有界效用 | 提醒候选二分类也是可行的对照 |
| SimPO | 偏好对 | 长度归一化 log-probability + 目标 margin | 理解长度偏差；本项目缺少生成概率 |
| ORPO | 偏好对 | SFT 加 odds-ratio 偏好项 | 学习正例与抑制负例可联合优化的思路 |
| GRPO / RLOO | 在线样本与 reward | 同题样本给 baseline，省去单独 critic | 课程关联知识，固定候选主线无需在线采样 |
| RLVR | 可验证 reward | reward 来自数学/代码检查器 | 训练标签来源可迁移；测试 gold 不可见 |

正温度缩放只改变概率尖锐程度，不改变同一组 logits 的 argmax。因此给最终排序 softmax 调 temperature 可以研究校准，单独使用它不能改善选择准确率。若以后做多个模型融合，温度会影响相对分数尺度，那是另外一个需独立验证的实验。

## 5. 已有算法方案库：保留为对照与扩展

本节保留第一版的候选级目标和特征想法。实际实施优先级已更新为 [答案组排序路线](MP2最终算法路线.md)，不再优先优化同答案组内的代表候选选择。

### 5.1 任务定义与监督标签

每道题 $i$ 有四个候选，输出的候选索引满足：

$$
\hat{j}_i\in\{0,1,2,3\}
$$

所选候选的解析答案与参考答案相等时，官方评分认定该次选择正确：

$$
\operatorname{parse}(candidate_{i,\hat{j}_i})=\operatorname{parse}(gold_i)
$$

训练标签最好保留为多正例集合 $Y_i$：若多个候选都解析为正确答案，它们都应算正例。不要强行规定每题只能有一个唯一正确 candidate。对于答案无法解析的候选，可显式加“无有效答案”特征；这些候选按官方评分不正确。

可训练候选级分数 $s_{ij}$，再在同一问题的四个候选间选最大。考虑多个正例的组内损失：

$$
L_i=-\log\sum_{j\in Y_i}\operatorname{softmax}(s_i)_j
$$

也可以先用线性/逻辑回归做简单基线，再看是否值得加模型复杂度。分组划分和评估都要以问题为单位，不能把同一道题的候选拆到不同 fold。

### 5.2 可用的轻量特征

**A. 解析答案与答案群体**

- 候选是否可被官方 parser 解析；最终答案是分数、整数还是小数。
- 同一答案在四个候选中出现的次数；该候选是否属于最大答案组；最大组与次大组票差。
- 四个候选答案是否完全相同、答案组是否打平、是否有多个有效答案。
- 答案格式信号：最后一个 ####、最后一个 boxed、是否只有数字尾项等。只把它们当证据，因为格式很容易模仿。
- 对解析出的有理数做等价规范化。不要只按字符串比较，也不要自己创建一套和官方 parser 不一致的评分规则。

**B. embedding 几何关系**

- 每个向量先做 L2 归一化，再算 4×4 cosine similarity。
- 候选的平均/中位数/最大非对角余弦相似度、最近邻、到中心的距离。
- 在同一最终答案组内的中心性，与跨答案组中心性分开计算。
- 几何证据与答案投票的交互：例如同答案候选彼此支持，是否比不同答案候选的语义簇更紧。
- 原始向量范数可单列作特征，与归一化方向分开；先验证范数是否含有效信息，不要让它意外主导距离。

**C. 文本结构特征**

- 候选总长度、最终答案附近的长度、数字/算术运算符数量。
- 是否给出明确最终答案标记、解析答案附近文本是否含单位或附加解释。
- 问题和解答的数字实体/单位是否大致匹配；算术步骤是否可抽取、相邻步骤能否用 Python Fraction 复算。
- 若实现简化的运算一致性检查，先限定支持的语法、写好失败回退；覆盖不了时返回“未知”，不要将解析失败当作候选错误。

最后一类的成本和误判风险最高。优先从答案组统计与 embeddings 开始，再做一组明确的文本特征消融，看是否有稳定收益。

### 5.3 原版实验顺序与保留用途

以下保留第一版实验构想，便于追踪方案演进；最终实施顺序与选型规则以新路线第 6–7 节为准。其中当前 hybrid 与对应投票基线在官方评分上等价，不能当成两项独立增益。

1. **答案投票 baseline：** 只按 parsed answer 分组投票；分别记录平票和没有有效解析答案的比例。
2. **嵌入 baseline：** 余弦相似度的全体中心性选择；再比较原始 L2 质心和归一化余弦中心性。
3. **当前 hybrid：** 多数答案优先，重复答案组里按 embedding 决胜；无有效答案时按全体 embedding 一致性选择。
4. **监督轻量 ranker：** 在训练集用 gold 产生正例标签，训练一个在同题候选之间排序的小模型；对比 NumPy 线性模型和一款易部署的小模型。限制模型尺寸并记录依赖。新路线进一步把排序单位明确为不同答案组。
5. **增量融合：** 分别加入答案特征、embedding 特征、文本结构特征与交互项。验证每一类是否提供独立增益。
6. **稳健性测试：** 候选重排后重新预测，确认算法不依赖候选的偶然排列；构造零向量/相同向量/空解析答案等边界输入检查回退路径。
7. **冻结与最终评估：** 只在验证集选配置；锁定代码、随机种子、checkpoint 和依赖，再按官方流程跑一次 test。测试集参考答案只用于最终官方评分，不能训练、挑特征或调阈值。

建议至少汇报官方 selection accuracy、每类错误（解析失败、答案平票、多数错、embedding 与投票冲突）、验证集与测试集的差异，以及全量 CPU 预测/评分时间和额外资产大小。核心消融是答案文本/最终答案、推理文本特征、固定 embeddings 三者各自贡献多少。

## 6. 对原基线的针对性阅读与修正结论

### 6.1 嵌入分支为什么无法提高原基线的官方得分

原基线代码入口见 [实现说明](../code/solution/README.md)。下面的推导对应该基线算法。

由 `code/common.py` 的评分定义可知：若两个候选的 `parse_answer` 结果相同，则它们对任意相同 gold 的得分相同。当前代码先确定答案组，随后只在组内用 embedding 选择代表候选，故这一步的任意替换都不会改变官方准确率。

如果四个候选都无法解析，任何选择都会被官方评分记为错误。该分支需要保证接口健壮，但不存在靠中心性提升这类输入官方得分的空间。若输入遵守“至少一个候选正确”的题库合同，全 None 情况本来就不会发生。

因此，**当前实现的官方得分与“按答案票数选组、平票取最早出现组”相同**，前提是代码正常运行。这个结论来自代码和评分函数的静态推导，本次没有训练或重新评测模型。原代码头部自述的历史成绩不作为新路线的实验结果。

### 6.2 保留的实现观察及其优先级

当前实现已经组合了两个课程相关思路：

1. 对四条候选调用官方 parse_answer，并按答案票数选组；若选中的组只有一个候选则直接返回，即便还有其他同票答案组。
2. 若多个候选共享领先答案，用 embedding 质心附近的候选作为该组代表；这不解决不同数值答案之间的冲突。
3. 若四条都没有有效答案，使用归一化 embedding 之间的平均 cosine similarity 选择整体更居中的候选。

它适合作为透明基线，但建议优先验证这些情况：

- **答案票数平局：** Python 的 max 在 key 分数相同的情况下保留先遇到的答案组。当前结果可能依赖候选排列；可在平票时明确使用所有并列答案候选的 embedding/文本证据，或设计独立的平票规则。
- **冲突处理的尺度：** 当前答案组质心距离用原始 embedding 的欧氏距离，而无有效答案路径用 cosine similarity。两种尺度都可保留为研究特征，但要放到跨答案组排序中比较才可能影响主指标。
- **中心性不是正确性：** 一个共同的错误解释也可能形成最紧密语义簇。尤其测试集答案冲突更明显时，需比较“答案投票正确率”“中心性正确率”“两者冲突时各自正确率”。
- **零向量边界：** 无有效答案分支把零范数替换成 1；零向量与自身余弦值仍是 0。若再统一减去 1 以排除对角线，不完全等价于减去真实对角值。可以显式把对角线置零，再取其余三项平均。此项是数值健壮性问题，不能解释当前方法官方准确率的变化。
- **评估正确目标：** 任何中间推理验证都只是额外特征；最后的选择必须按官方 final-number parser 对齐。

## 7. 最值得优先验证的想法

**第一优先：按相同解析答案分组，结合答案票数、归一化 embedding 和局部文本证据，学习不同答案组之间的排序。** 同题只有一个有效答案组时直接返回；多个答案组时才需要模型。具体的特征定义、网络结构、损失与验收规则见 [最终实施路线](MP2最终算法路线.md)。

一个清晰实验可以回答：

- 单纯答案多数投票是否对容易样本有效、在 hard test 上退化？
- 语义中心性是否只是在复现多数票，还是在票数冲突时提供新增信息？
- 文本长度和 boxed/#### 格式是否真预测正确，还是只诱发短、规整答案偏差？
- 轻量监督模型能否学到“答案一致但推理套路不同”的关系？
- 排序器的高置信度是否更准确？可按验证集 confidence 分桶，检查 calibration；不要把置信度直接等同于 correctness。

如果答案组排序模型只比简单 baseline 多一点点准确率，就应结合波动与成本判断是否值得增加复杂度。若增益稳定，再记录可复现的消融、资源消耗和典型失败案例。报告要解释证据，而不只报一个分数。

## 9. 从知识点到执行方案的保留清单

| 原有或新增思路 | 保留方式 | 优先级与理由 |
|---|---|---|
| 多数投票 | 现有 baseline，并作为显式票数特征 | 必做；成本低，能量化多数票错误 |
| 全体/答案组 embedding 中心性 | 跨答案组基线与几何特征 | 必做；原先仅组内使用的方式没有得分贡献 |
| 候选二分类、多正例 candidate loss | 与答案组 CE 对照 | 可选；解释目标粒度及重复答案的隐式加权 |
| 答案组交叉熵 | 主训练目标 | 主线；每题恰好一个正确解析答案组 |
| Bradley–Terry 成对排序 | 同特征、同网络的损失消融 | 次优先；来源于 Lecture 6 reward model |
| 格式、长度、自信措辞 | 便宜特征/风格偏差对照 | 必须单列消融，避免误称理解推理 |
| 题目条件与局部算术 | 后续增量特征 | 只接受可测的独立增益，未知不等于错误 |
| 加权投票、log-sum-exp 聚合 | 保留为可控 count prior 的扩展 | 主线不叠加，以免重复计算多数票证据 |
| PCA/低秩、小型 MLP、树模型 | 容量与压缩备选 | 先线性模型和一个小 MLP，避免同时开启大量模型搜索 |
| 不确定性和校准 | train 内 OOF 拟合、validation 报告 | 诊断用途；接口仍必须选择一个候选 |
| 多模型集成、复杂门控 | 有稳定互补错误证据后再考虑 | 非默认；需要同时计算资源和额外资产 |
| 在线 CoT、ReAct、自我修订、LLM judge、LoRA/RL 训练大模型 | 课程知识保留 | 不纳入当前固定候选、无额外权重的部署方案 |
